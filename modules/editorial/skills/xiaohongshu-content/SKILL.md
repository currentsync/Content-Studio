# Xiaohongshu Content

Require the current Core and BaseContent paths from the project snapshot plus `channel=xiaohongshu`, `format=graphic|video`. Block unknown formats. Never infer BaseContent from an existing Bilibili plan.

## Shared procedure

1. Select one coherent coverage slice that can deliver a clear task, knowledge map, workflow, comparison, evaluation, result analysis, or mechanism.
2. Preserve necessary dependencies and explicitly list uncovered BaseContent units.
3. Make every unit perform one cognitive action; remove decorative examples and platform slang.
4. Put evidence and boundaries next to the claim they qualify.
5. Save the result to the target channel's `content.md`; return the artifact path and references to Workflow for status registration. Do not edit the project snapshot..

## `format=graphic`

- Design page-level knowledge units, not narration chunks.
- After the cover, establish scope, object, and what the reader can take away.
- Use map, step, checklist, comparison, diagnosis, annotated evidence, example, result, limitation, or index units.
- Make the swipe order cumulative while allowing a reader to relocate a saved page.
- Set `opening_handoff` to the first body page/lead paragraph after packaging.

## `format=video`

- Keep one dominant understanding path.
- Show the object/task quickly, then advance through one demonstration, case, comparison, or process.
- Cut branches; never speed-read a Bilibili structure.
- Set `opening_handoff` to the first body beat after the channel opening.

Do not add cover design, big-text rules, title candidates, note caption copy, hashtags, or engagement CTAs.
