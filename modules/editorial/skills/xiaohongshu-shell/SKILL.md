# Xiaohongshu Shell

Read `../../theory/shell-theory.md` and the complete Xiaohongshu section of `../../theory/channel-adaptation-theory.md`.

Require the current Core and selected BaseShell paths from the project snapshot plus `channel=xiaohongshu`, `format=graphic|video`. Reject unknown formats and mismatches.

## Procedure

1. Extract the BaseShell's invariant object, real problem/task, tension, and bridge to Core.
2. Choose one high-density slice rather than carrying the whole issue.
3. Make the object and current user task explicit.
4. Define an honest, quickly judgeable content promise such as a map, workflow, checklist, evaluation frame, build record, result analysis, or usable mechanism.
5. For graphic, optimize the semantic promise for scan/save/revisit. For video, ensure the slice can be shown or narrated through one dominant path.
6. Generate 3–5 distinct candidates and state `preserved_base`, `selected_slice`, `task_or_dilemma`, `content_promise`, `bridge_to_core`, and `risks`.
7. Reject title-only wordsmithing, broad industry theses, false certainty, and visual/typographic cover rules.

Return concise candidates in the conversation. Do not select a winner or create Title, Opening, Thumbnail, body pages, or scripts. After the user chooses, save only the selected result to the channel's `shell.md`; return the artifact path and references to Workflow for status registration. Do not edit `project.yaml`..
