# Shell Theory

## 1. 基本关系

- **Core**：真正要讲的知识、判断、原理、经验或结论。
- **BaseShell**：平台无关、目标受众熟悉的具体问题、场景、冲突、异常、对象、实验或任务。
- **ChannelShell**：从已选择 BaseShell 中为一个渠道与 format 实例化出的传播切面。
- **Title**：Shell 的语言化压缩。
- **Opening**：Shell 的叙事化展开。
- **Thumbnail**：Shell 的视觉化表达。

> Core 决定内容价值，BaseShell 决定母入口，ChannelShell 决定该渠道的具体入口。

两级 Shell 都不是 Core 的口语化改写，也不是流量装饰。它们让抽象、专业或不可直接感知的 Core，从受众已能识别的现实入口变得可进入。

## 2. 成立条件

一个有效 Shell 必须同时满足：

1. **熟悉**：目标受众能快速识别。
2. **具体**：能感知为情境、行为、对象、事件或任务。
3. **有真实张力**：存在问题、异常、冲突、对比或目标。
4. **可展开**：能自然支撑 Title、Opening 与 Thumbnail。
5. **可解释**：Core 确实能解释、处理或照亮该 Shell。
6. **适配受众**：不是为了泛流量偏离核心人群。

无关热点、纯猎奇、虚假冲突与无法由 Core 兑现的承诺不是 Shell。

## 3. 探索维度

- 场景型：受众经历过的具体情境。
- 异常型：预期与结果之间的可感知落差。
- 对比型：两种做法、对象或结果的真实差异。
- 任务型：受众确实需要完成的目标。
- 实验型：用可执行测试显现 Core。
- 对象型：从熟悉的工具、产品、行为或物体进入。

类型用于扩展候选空间，不是配额。多个候选必须代表不同入口，而非同一句话的措辞变化。

## 4. 选择权

Core → BaseShell 与 BaseShell → ChannelShell 都产出候选集，不默认存在唯一最佳答案。用户根据真实意图、受众和内容策略明确选择；Agent 可以说明差异和风险，但推荐不能替代选择。

选择后用独立 BaseShell Selection 或 ChannelShell Selection 固定 Candidate Set revision 与 candidate id。Title、Opening、Thumbnail 只接受 ChannelShell Selection。需要换壳时创建新 Selection，并重新生成受影响的包装产物。

## 5. 下游一致性

### Title 与 Opening

二者是同一个 Shell 的不同时间尺度。Title 建立承诺，Opening 立即兑现：共享中心对象、场景和张力，并自然过渡到 Core。若观众会感觉“点进来是另一个问题”，配对即失败。

### Thumbnail

封面优先表现 Shell 中最可见的“对象 + 关系”，回答“正在发生什么”，而不是“抽象主题叫什么”。优先级：具体场景 → 人物与对象关系 → 对象间关系 → 可见冲突 → 空间关系 → 信息环境 → 最后才是抽象隐喻。

### 与主体内容的交接

Opening 负责把受众从 Shell 带入 Core；主体内容从该交接后开始，不再制造第二个无关钩子。Shell 不应侵占全部主体，也不能让主体偏离 Core。

## 6. 退回条件

若输入只是专业术语、抽象主题、Core 同义句，或 Core 无法兑现其问题/冲突，应退回 Core → Shell；下游不得临时修补或偷偷替换。
