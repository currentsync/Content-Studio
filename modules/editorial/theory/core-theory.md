# Core Theory

## 1. 定义

**Idea** 是尚未稳定的观察、疑问、直觉、类比或部分判断。它可以含糊、矛盾或错误。

**Core** 是用户已经理解并确认、在限定范围内有知识支撑、可供后续创作使用的内容命题。Core 不是主题标签、标题、传播钩子、脚本或一句更有气势的口号。

Core 的作用是回答：

> 这次内容真正要让人理解什么？我们凭什么这样说？说到哪里停止？

## 2. 形成路径

```text
Idea
→ 澄清可能含义
→ 用户确认意图
→ 映射真实知识与争议
→ 最低充分学习
→ 用户形成并确认观点
→ Core Package
```

这是交互式认知过程，不是一次性文案生成。Agent 可以提出解释候选、寻找证据、指出矛盾和教授概念；用户拥有观点、范围和价值判断。

## 3. 认识论分层

关键表述应能区分：

1. **充分支持的知识**：有强且相关的证据或稳定定义。
2. **理论/模型**：能组织解释，但不等于已证实事实。
3. **争议或有限结论**：证据混合、间接、初步、情境依赖或存在反例。
4. **用户解释/价值判断**：由用户承担的推断、选择或创作立场。

合理的故事、知名概念和看似可信的机制都不能自动成为证据。相关不等于因果。表达确定性不得高于证据与用户理解所支持的程度。

## 4. 最低充分学习

用户不需要成为学术专家，但至少应能：

- 用自己的话说出核心区别；
- 说明主要依据；
- 指出一个重要限制或反面情形；
- 避免最关键的误导性夸大；
- 自己选择本期范围和观点。

若缺口会实质改变 Core，必须继续澄清或学习，不能为了推进 Workflow 跳过。

## 5. Core Package

```yaml
core_statement: "中心知识或判断"
knowledge_basis:
  - claim: "关键支撑"
    provenance: source_supported
    evidence_refs:
      - label: "来源名称"
        uri: "来源地址"
    confidence: medium
scope: "本期覆盖范围与终点"
key_points:
  - "必须讲清的 2–4 点"
not_claiming:
  - "明确不主张什么"
uncertainties:
  - "仍存争议、限制或弱证据"
```

`not_claiming` 与 `uncertainties` 不是附注，而是 Core 的组成部分。下游在最容易误解的位置呈现边界，不得只在结尾免责。

## 6. 稳定性门禁

可进入下游的 Core 必须：

- `core_statement` 明确且内部一致；
- `knowledge_basis` 能在 `scope` 内支撑主张；
- `key_points` 构成可解释路径；
- `not_claiming` 与 `uncertainties` 阻止主要过度推断；
- 用户明确确认该精确 revision 代表其观点。

Core 更新时创建新 revision。旧下游不会自动改绑到新版；它们保留历史有效性与可追溯性。

## 7. 下游边界

confirmed Core 同时进入两条路径：

- 内容路径：Core → Editorial Plan；
- 包装路径：Core → Shell → Title / Opening / Thumbnail。

下游可以改变顺序、媒介和表达，但不能增强主张、隐藏不确定性、添加虚构证据或把 Agent inference 冒充用户观点。
